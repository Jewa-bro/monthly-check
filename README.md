# 생수

생수 배송 건수를 일별로 기록하고, **정산월** 누적 실적과 금액을 확인하는 앱입니다.
정산 기간은 매월 26일부터 다음달 25일까지이고, **기간이 끝나는 달**로 부릅니다 (7월 26일 ~ 8월 25일 = 8월).
브라우저에서 열어 **카카오 계정으로 로그인**하면 바로 쓸 수 있고, 폰에서는 앱처럼 설치할 수 있습니다.

## 폰에 설치하기

1. 폰 브라우저로 배포된 주소를 엽니다.
2. **안드로이드(Chrome)**: 우측 상단 `⋮` → **앱 설치** (또는 홈 화면에 추가)
   **아이폰(Safari)**: 하단 공유 버튼 → **홈 화면에 추가**
3. 홈 화면에 생긴 아이콘으로 열면 브라우저 주소창 없이 앱처럼 실행됩니다.
4. **첫 로그인 때는 인터넷이 필요합니다.** 한 번 로그인한 뒤에는 인터넷이 없어도 열리고 입력할 수 있습니다.

## 사용법

- **기록하기**: 홈 아래 **실적 기록하기** → 숫자 입력 → **저장하기**. 날짜는 오늘로 시작하고, 제목 아래 날짜 알약을 눌러 다른 날로 바꿉니다.
- **여러 날 한꺼번에**: 기록하기 화면 안의 **여러 날 한꺼번에 입력하기**. 날짜가 쭉 나열되고 칸마다 건수를 넣어 한 번에 저장합니다. 바꾼 날 수가 버튼에 표시됩니다.
- **고치기·지우기**: 홈의 날짜 목록에서 그 날을 누르면 수정 화면으로 들어갑니다.
- **달 바꾸기**: 홈 맨 위 `2026년 8월 ▾` 를 눌러 고릅니다.
- **단가**: 홈의 `건당 단가` 줄에서 넣습니다. 매일 넣지 않습니다 — **한 번 넣으면 바꿀 때까지 계속 적용**되고, 바꾸면 그 날부터 새 단가가 적용됩니다. 첫 단가는 `처음부터`로 저장되어 나중에 채우는 과거 기록에도 적용됩니다.

### 단가 계산 방식

단가는 달이 아니라 **날짜**에 딸립니다. `2026-07-28부터 1,600원`처럼 저장되고, 어떤 날의 단가는 그 날 이전의 가장 최근 변경값입니다. 그래서 정산 기간 중간에 단가가 바뀌어도 금액이 날짜별로 정확히 계산됩니다.

```
7월 26일 118건 × 1,500원
7월 27일  96건 × 1,500원
7월 28일 132건 × 1,600원   ← 이 날부터 단가 변경
             합계 532,200원
```

### 글쓰기·표시 규칙

- 모든 안내 문장은 **해요체**로 통일합니다 (`저장했어요`, `적용돼요`). 버튼만 `저장하기` 같은 명사형입니다.
- 화면의 주인공 숫자는 **항상 건수**입니다. 금액은 단가가 있을 때 그 아래 한 단계 작게 붙는 파생값입니다.

### 안드로이드 뒤로가기

화면마다 브라우저 히스토리 항목을 쌓아 시스템 뒤로가기와 연결했습니다.

- `홈 → 기록하기 → 날짜 선택 시트` 에서 뒤로가기를 누르면 시트 → 기록하기 → 홈 순서로 되돌아가고, 홈에서 한 번 더 누르면 앱이 닫힙니다.
- 저장을 마치면 깊이와 무관하게 홈으로 돌아갑니다 (뒤로가기로 입력 화면에 되돌아가지 않습니다).
- 화면 안 왼쪽 위 뒤로가기 버튼도 시스템 뒤로가기와 똑같이 동작합니다.
- 히스토리 항목에는 그 화면을 되살릴 상태를 스냅샷으로 담습니다. 그래서 시트를 여닫아도 입력 중이던 값이 사라지지 않습니다.

### 화면 조작 규칙

혼동을 줄이려고 버튼 모양의 역할을 하나로 고정했습니다.

| 모양 | 뜻 |
| --- | --- |
| 왼쪽 위 진한 화살표 (한 화면에 하나만) | 뒤로 가기 |
| 글자 + 아래쪽 캐럿 `▾` | 값 고르기 (아래에서 선택 창이 올라옴) |
| 줄 오른쪽의 연한 꺾쇠 `›` | 그 줄로 들어가기 |

## 데이터

기록은 **카카오 계정으로 로그인한 뒤 Firestore 에만** 저장됩니다. 기기에는 저장하지 않습니다.

- 로그인해야 쓸 수 있습니다. 폰을 바꾸거나 앱을 지워도 같은 카카오 계정으로 로그인하면 그대로 이어집니다.
- Firebase 로그인에는 카카오 제공업체가 없어서, 카카오가 확인해 준 사람을 Firebase 가 인정하는
  토큰으로 바꿔주는 서버를 한 번 거칩니다 (`worker/kakao-login.js`, Cloudflare Workers).
  로그인할 때만 호출되고, 기록을 읽고 쓰는 것은 앱이 Firestore 와 직접 하므로 그 서버가 멈춰도
  이미 로그인한 사람은 계속 씁니다. uid 는 `kakao:<사용자번호>` 로 고정됩니다.
- 인터넷 사용 기록·쿠키·캐시를 지워도 기록은 남습니다.
- 값을 바꾸면 **바뀐 날짜만** 서버로 올립니다. 통째로 덮어쓰지 않으므로 다른 날 기록을 잃지 않습니다.
- 다른 기기에서 고치거나 지운 것이 화면에 바로 따라옵니다. 단, 입력 중인 화면은 건드리지 않습니다.
- 한 번 로그인한 뒤에는 **인터넷이 끊겨도 읽고 쓸 수 있고**, 연결되면 자동으로 올라갑니다
  (Firestore 자체 캐시).
- 동기화 상태는 화면에 표시하지 않습니다. 사용자가 그걸 보고 할 수 있는 일이 없고, 저장됐다는
  확인은 저장 직후의 토스트와 목록의 숫자가 이미 해줍니다. 대신 **정말 저장에 실패했을 때만**
  `저장하지 못했어요` 토스트를 띄웁니다 (규칙에 막힌 경우 등. 인터넷이 없는 것은 실패가 아니라
  대기입니다).
- **되돌리기는 없습니다.** `전체 기록 삭제` 를 확인까지 누르면 계정에서 지워지고 복구할 방법이 없습니다.

접근 규칙은 로그인한 본인의 `users/{uid}` 아래만 읽고 쓸 수 있게 제한돼 있습니다.

## 구성

| 파일 | 설명 |
| --- | --- |
| `index.html` | 앱 전체 (HTML·CSS·JS 한 파일) |
| `manifest.webmanifest` | 앱 이름·아이콘·실행 방식 |
| `sw.js` | 앱 파일과 Firebase SDK 를 미리 받아두는 서비스워커 |

| `icon-*.png` | 앱 아이콘 |
| `android/` | APK 프로젝트 (아래 참고 — **빌드 검증 안 됨**) |

## android/ 폴더에 대해

`index.html` 을 그대로 담아 실행하는 완전 오프라인 APK 프로젝트입니다. 코드는 다 있지만
**한 번도 성공적으로 빌드된 적이 없습니다.** 쓰지 않는 폴더이니 무시하면 됩니다.

- 개발 PC 에서 Gradle 이 `Unable to establish loopback connection` 으로 실패합니다.
  일반 소켓은 되는데 `Selector.open()` / `Pipe.open()` 만 실패합니다. 금융·공공 사이트용
  보안 프로그램(delfino, veraport)이 윈도우 Java NIO 의 루프백 자기검증을 깨뜨리는
  알려진 증상입니다. Android Studio 로 열어도 같은 Gradle 을 쓰므로 동일하게 실패합니다.
- GitHub Actions 로 옮겨 빌드하려 했지만, 결국 **APK 가 PWA 대비 얻는 것이 거의 없어서
  중단했습니다.** PWA 도 홈화면 아이콘·전체화면·오프라인·시스템 뒤로가기가 다 되고,
  고쳤을 때 재설치가 필요 없다는 점에서 오히려 낫습니다.
- 다시 하려면: `android/ci-build.sh` 를 실행하는 워크플로 파일을 추가하고, 서명 키를
  `ANDROID_KEYSTORE_BASE64` 등 Secret 으로 넣으면 됩니다.
